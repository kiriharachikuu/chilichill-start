# 厚嘴唇空间站 Spec

## Why
ChiliChill 粉丝的 Q群与自制站点（小游戏、工具、小测试）目前散落在聊天记录和私域分享中，缺少统一收录与质量把关。本版搭建一个带投稿、审核、分类能力的粉丝导航站，把分散资源集中呈现，并为后续画廊、音乐厅等模块预留干净的扩展位。

## What Changes
- 新建 npm workspaces 前后端分离工程：`apps/web`（React + Vite + TS + Tailwind）、`apps/api`（Fastify + Prisma + SQLite）、`packages/shared`（共享类型与 Zod 校验）。
- 前端公开站：首页、Q群导航、网站导航、统一投稿、我的投稿、登录注册。
- 后台管理端：审核台（待审列表 + 详情 + 通过/驳回）、内容管理、标签管理、分类规则（城市大区映射 + 关键词自动打标）、用户列表。
- 后端 REST API：JWT（httpOnly Cookie）认证与 `USER`/`ADMIN` 角色、RBAC 守卫、Zod 入参校验、限流。
- 分类能力：投稿表单先单选「群类型」（地区粉丝群 / 线上功能群 / 其他），**地区粉丝群才展开城市勾选选择框**；所选城市自动映射大区；线上功能群按功能标签归类（关键词规则仅作辅助推荐）；其余由管理员自定义标签归类。
- 审核能力：新建与修改统一走 Submission 草稿，审核通过后才写入线上内容；修改不覆盖线上数据直到通过。
- 存储能力：上传走统一存储适配器，默认本地 `public/uploads`，配置腾讯云 COS 密钥后切换为 COS 直传（服务端签名）。
- 扩展能力：投稿内核按 `entityType` 字符串 + 校验器/落地器注册表设计，新增画廊、音乐厅等模块无需改动审核流程。
- 交付 `EXTENDING.md`（扩展对接说明）与可一键启动的种子数据。

## Impact
- Affected specs：全新建站，无既有能力被修改。
- Affected code：仓库根目录新建 `package.json`、`apps/`、`packages/`、`.env.example`、`README.md`、`EXTENDING.md`。

## ADDED Requirements

### Requirement: 前后端分离工程与本地可运行
系统 SHALL 以 npm workspaces 单仓多包结构组织，前端与后端独立启动、通过 `/api` 代理通信，并提供开箱即用的种子数据与启动脚本。

#### Scenario: 本地一键启动
- **WHEN** 开发者执行根目录 `npm install` 与 `npm run dev`
- **THEN** 前端可访问且页面正常渲染，后端 `/api/health` 返回 200，数据库已建表并写入种子数据

### Requirement: 用户与权限系统
系统 SHALL 提供注册、登录、登出、获取当前用户能力；密码使用 bcrypt 哈希存储；登录态通过 httpOnly Cookie 承载 JWT；仅 `ADMIN` 角色可访问 `/api/admin/*` 接口与后台页面。

#### Scenario: 普通用户访问后台
- **WHEN** 已登录的普通用户访问后台接口或 `/admin` 页面
- **THEN** 接口返回 403，页面提示无权限并阻止进入

#### Scenario: 登录失败
- **WHEN** 用户输入错误密码
- **THEN** 返回 401 且不泄露账号是否存在

### Requirement: Q群导航与「群类型优先」分类
系统 SHALL 提供 Q群导航页，展示已审核通过的群组（群名、群号、群类型、城市、大区、标签、简介、加入方式/二维码），支持按大区、群类型、标签、关键词筛选与分页；群号支持一键复制。

投稿表单 SHALL 先要求单选群类型，再按类型渲染不同字段：
1. `REGION` 地区粉丝群：必须展开城市勾选选择框（按大区分组、可搜索，勾选一个主城市），城市命中映射表后自动归属对应大区（如广州 → 华南）。
2. `ONLINE` 线上功能群：必须选择功能标签（如应援企划、二创交流、资源分享、闲聊灌水、活动组织），不显示城市选择框；群名/简介关键词规则仅用于辅助推荐标签。
3. `OTHER` 其他：不显示城市选择框，填写用途说明，由管理员自定义标签完成分类。

群名不包含城市名或「粉丝群」字样不影响分类，分类结果以群类型与所选字段为准；管理员可在审核时修正大区与标签。

#### Scenario: 地区群按勾选城市归类
- **WHEN** 投稿人选择「地区粉丝群」并在城市选择框中勾选「广州」
- **THEN** 表单实时显示「华南大区」预览，审核通过后该群归入华南大区，与群名是否含「广州」无关

#### Scenario: 线上功能群不出现城市选择
- **WHEN** 投稿人选择「线上功能群」并勾选「应援企划」标签
- **THEN** 城市选择框不显示，群组按「应援企划」标签归类

#### Scenario: 其他类型
- **WHEN** 投稿人选择「其他」类型并提交
- **THEN** 城市与大区标记为「待定」，管理员审核时必须至少指定一个自定义标签后才能通过

### Requirement: 网站导航
系统 SHALL 提供网站导航页，展示已审核通过的粉丝自制站点（名称、链接、简介、封面、标签），支持标签筛选、关键词搜索与外链安全跳转（`noopener noreferrer`）。

#### Scenario: 按标签筛选站点
- **WHEN** 用户点击「小游戏」标签
- **THEN** 列表仅展示带该标签且已发布的站点

### Requirement: 统一投稿与审核
系统 SHALL 提供标准化投稿表单（群 / 网站两类），字段级校验，支持封面上传；所有新建内容与修改内容均生成 `PENDING` 状态的 Submission，不直接改动线上数据；管理员通过后按实体类型写入或更新线上内容，驳回需填写原因且线上内容保持不变。

#### Scenario: 新建投稿通过
- **WHEN** 管理员在审核台通过一条群投稿
- **THEN** 系统创建对应群记录并立即可在前端公开列表展示，投稿状态变为「已通过」

#### Scenario: 修改线上内容需二次审核
- **WHEN** 投稿人修改一条已发布的网站信息
- **THEN** 生成 UPDATE 类型投稿，原网站保持当前展示内容；审核通过后才覆盖字段并同步展示新内容

#### Scenario: 驳回
- **WHEN** 管理员驳回投稿并填写原因
- **THEN** 投稿状态变为「已驳回」，投稿人可在「我的投稿」看到原因并修改后重新提交

### Requirement: 资源上传与对象存储
系统 SHALL 提供图片上传接口，限制类型（png/jpg/jpeg/webp）与大小（≤5MB）；存储层采用适配器，默认写入本地并由后端静态服务，配置 `COS_SECRET_ID`/`COS_SECRET_KEY`/`COS_BUCKET`/`COS_REGION` 后切换为腾讯云 COS 并返回可访问 URL。

#### Scenario: 非法文件上传
- **WHEN** 上传 gif 或超过 5MB 的文件
- **THEN** 返回 400 并说明限制，不写入存储

### Requirement: 后台内容与配置管理
系统 SHALL 提供管理员后台，支持：审核队列（按类型/状态筛选、查看投稿详情与修改差异）、已发布内容管理（下线/编辑）、标签 CRUD（名称、slug、适用范围、颜色）、城市大区映射维护、关键词自动打标规则维护；审核时可修正群类型、大区与标签。

#### Scenario: 新增自定义标签
- **WHEN** 管理员创建标签「深夜电台」并设置适用范围为群
- **THEN** 该标签立即出现在投稿表单与群导航筛选器中

#### Scenario: 审核时修正分类
- **WHEN** 管理员在审核详情中把群类型从「其他」改为「地区粉丝群」并指定城市
- **THEN** 系统按新类型重新计算大区，通过后以修正后的分类发布

### Requirement: 可扩展接口（画廊 / 音乐厅预留）
系统 SHALL 以实体注册表抽象投稿与审核：实体类型以字符串标识，配套校验器与落地器；前端导航模块以配置数组驱动；新增模块仅需注册新实体、校验器、落地器与页面，无需改动审核核心。

#### Scenario: 新增内容类型
- **WHEN** 后续新增「画廊」实体类型
- **THEN** 只需注册 `GALLERY` 校验器/落地器与对应后台表单，即可复用现有投稿、审核、标签与上传能力

### Requirement: 界面与适配
系统 SHALL 采用深空星轨视觉（深色宇宙背景、星点氛围、暖色高亮）提供友好交互；页面在 375px 起的移动端与桌面端均可正常使用；关键操作（复制群号、提交、审核）有明确的加载与结果反馈。

#### Scenario: 移动端浏览
- **WHEN** 用户在 375px 宽屏幕打开首页与群导航
- **THEN** 布局单列自适应，无横向溢出，筛选控件可操作
